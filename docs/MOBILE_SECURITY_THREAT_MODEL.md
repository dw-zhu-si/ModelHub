# ModelHub 移动访问威胁模型

状态：Phase 1 实现基线<br>
最后复核：2026-09-27<br>
范围：桌面移动访问服务、iPhone/iPad 客户端、Android 手机/平板客户端，以及局域网或用户自有 VPN 内的配对和只读概览。

## 1. 安全目标

1. 移动设备永远拿不到供应商 API Key、OAuth 刷新令牌、代理订阅 URL 或桌面全局网关令牌。
2. 移动访问默认关闭，且不改变现有 `127.0.0.1:11435` 本地 API 的绑定、令牌或权限。
3. 首次信任必须同时依赖二维码中的证书指纹、短时单次配对秘密和桌面用户显式批准。
4. 配对后每个设备使用自己的不可导出私钥；复制请求、窃取设备 ID 或知道服务地址都不能代替设备签名。
5. 只读概览遵循最小披露；撤销设备、关闭移动访问或重启配对流程都不得破坏供应商、路由、健康和用量数据。

## 2. 资产与信任边界

| 资产 | 权威位置 | 移动端是否持有 |
| --- | --- | --- |
| 供应商 API Key / OAuth 令牌 | macOS Keychain | 否 |
| 桌面网关 Bearer Token / Agent Token | macOS Keychain | 否 |
| 代理订阅 URL | macOS Keychain | 否 |
| 桌面 TLS 私钥 | macOS Keychain，`ThisDeviceOnly` | 否 |
| 移动设备 P-256 私钥 | iOS Secure Enclave/Keychain 或 Android Keystore | 是，不导出 |
| 设备公钥、权限、撤销状态 | 桌面移动访问存储 | 只有自身设备 ID 与权限摘要 |
| 配对秘密 | 二维码与进程内短时状态 | 配对期间仅驻留内存，不持久化 |
| 只读概览缓存 | 移动设备应用私有存储 | 是，不含秘密、URL、正文 |

信任边界包括：二维码展示到相机/剪贴板、移动设备到桌面 TLS 连接、桌面 UI 的批准动作、平台安全存储、局域网/VPN，以及桌面持久化的设备授权记录。

## 3. 攻击者模型

- 同一局域网中的被动监听者或主动中间人。
- 获得二维码截图但没有桌面批准能力的人。
- 知道服务地址、设备 ID 或曾经捕获合法请求的人。
- 已被撤销或丢失的移动设备。
- 向配对/移动接口发送超大、畸形、高频或越权请求的客户端。
- 能控制移动设备剪贴板、备份或应用沙盒之外日志的本地软件。

不在 Phase 1 保证范围内：已取得桌面用户会话与 Keychain 访问权限的攻击者、越狱/root 后能够读取应用进程内存的攻击者，以及被平台根证书/内核完全攻破的设备。

## 4. 协议与控制

### 4.1 首次配对

- 二维码配对会话默认 120 秒过期，最多 8 个并行会话；一次性秘密使用系统安全随机数生成。
- 二维码使用 HTTPS 地址和 64 位十六进制 SHA-256 证书指纹；客户端拒绝 HTTP、带凭据、查询参数或片段的地址。
- 客户端固定叶证书指纹，拒绝重定向、Cookie、共享缓存和超限响应；不通过“忽略 TLS 错误”回退。
- 提交成功只进入 `awaiting_approval`。Mac 显示设备名称和 P-256 公钥指纹，用户必须显式批准；默认只授予 `viewer`。
- 错误配对秘密最多尝试 5 次；会话成功提交后立即失效。审批请求另有 5 分钟上限和设备容量上限。

### 4.2 已配对请求

- 规范化字符串绑定协议版本、设备 ID、Unix 时间戳、nonce、HTTP 方法、路径和请求体 SHA-256。
- 设备使用 P-256 ECDSA/SHA-256 签名。服务端只接受 `/mobile/v1/` 路径、固定方法集合和有界请求体。
- 时间偏差上限 90 秒；nonce 在 180 秒窗口内只能使用一次，每设备最多保留 512 个 nonce，达到容量后失败关闭。
- 未知、已撤销、权限不足、签名无效、时间过期、nonce 重放或容量耗尽均不会返回概览。
- Phase 1 只有 `GET /mobile/v1/bootstrap` 通过设备认证；配对端点与现有 `/v1` Bearer 接口完全分离。

### 4.3 数据最小化

`bootstrap` 只返回协议/网关版本、生成时间、网关运行状态、默认健康模型、启用供应商/路由数量、聚合模型健康和供应商健康摘要。明确排除：API Key、OAuth 令牌、桌面/Agent Token、Base URL、订阅 URL、完整配置、请求头、提示词、模型响应正文和上游错误正文。

响应统一设置 `Cache-Control: no-store`。移动端离线缓存只保存上述非秘密概览，并显示更新时间，不把缓存伪装成实时状态。

## 5. 威胁、缓解与验证

| 威胁 | 缓解 | 当前验证 |
| --- | --- | --- |
| 局域网中间人替换桌面服务 | 二维码带证书 SHA-256 指纹；客户端固定叶证书；只允许 TLS 1.3；拒绝重定向 | TLS 单元测试、真实本机固定证书握手测试、iOS/Android 传输代码审查 |
| 二维码泄露后自动获得权限 | 2 分钟单次秘密 + Mac 显式批准 + 公钥指纹展示 | 成功、过期、错误秘密、重复提交与批准测试 |
| 捕获请求后重放 | 时间戳窗口、单次 nonce、设备签名绑定方法/路径/正文 | 规范化向量、过期、重放、正文篡改测试 |
| 设备 ID 被枚举或伪造 | 没有对应私钥无法通过 P-256 验签；错误统一失败关闭 | 无效签名与未知设备测试 |
| 丢失设备继续访问 | Mac 可撤销；服务端每次请求检查撤销状态并清除 nonce 状态 | 撤销后授权失败测试 |
| 越权访问管理或供应商秘密 | 独立 `/mobile/v1` allowlist、权限检查、专用 DTO、不复用桌面 Token | 路由 allowlist 与输出负向测试 |
| 超大/畸形输入耗尽资源 | 配对体 16 KiB、签名体 1 MiB、响应 1 MiB、路径/名称/密钥长度、会话/设备/nonce 容量上限 | 边界和容量测试；后续补充模糊测试 |
| 私钥通过备份迁移或导出 | Apple 使用 `ThisDeviceOnly` 与 Secure Enclave（设备）；Android 使用 Keystore EC KeyPair | 编译与代码审查；真机硬件属性待验收 |
| 秘密进入日志或缓存 | 移动 DTO 不含秘密字段；临时配对秘密只在内存；不记录正文；HTTP 缓存禁用 | 源码扫描、DTO 负向测试；运行日志真机复核待完成 |
| 公网意外暴露 | 功能默认关闭；单独监听；文档只支持局域网/用户 VPN；不建设公共中继 | 默认状态与绑定回归测试；家庭/企业网络真机复核待完成 |

## 6. 生命周期与恢复

- 关闭移动访问时停止 TLS listener，并清空未完成的配对会话与审批；现有桌面回环 API 保持运行。
- TLS 身份首次启用时生成并存入 Keychain。若证书/私钥丢失或轮换，旧指纹不再匹配，客户端必须重新扫码配对；不得静默接受新证书。
- 设备丢失时从 Mac 撤销对应设备。Phase 1 不提供移动端自助解除撤销，因为这会弱化桌面权威边界。
- 用户在 App 内选择“忘记设备”时，客户端先删除 Secure Enclave/Keychain 或 Android Keystore 中的设备私钥，再删除设备 ID 与概览缓存；密钥删除失败时不伪装成解绑成功。
- 删除移动 App 后，平台私钥与应用数据随应用沙盒/Keychain 策略处理；重新安装必须重新配对，不能依赖旧二维码或复制设备 ID。
- 桌面持久化失败时移动服务失败关闭；不得为恢复可用性而绕过签名、撤销或 TLS 固定。

## 7. 剩余风险与关闭门禁

以下项目在完成前不得宣称 Checkpoint A 或生产移动版已经关闭：

1. 四类真实设备完成扫码、桌面审批、概览刷新、离线缓存、恢复连接与撤销 E2E。
2. 真机核验 iOS Secure Enclave 与 Android Keystore 生成的密钥不可导出，且备份/换机后不会复用设备身份。
3. 局域网隔离、双栈 IPv4/IPv6、用户自有 VPN、路由器客户端隔离和系统本地网络权限场景测试。
4. 证书轮换与设备丢失演练；确认 UI 明确要求重新配对，不出现“接受任意证书”入口。
5. 对配对解析、HTTP 边界和签名头执行模糊测试；建立并发、连接数、CPU、内存和电量基线。
6. VoiceOver、TalkBack、最大字体、提高对比度、减少动态效果、旋转、分屏和后台/前台切换验收。
7. App Store 隐私清单、Google Play Data safety、相机/本地网络用途说明与隐私政策在发布前复核。

## 8. 回滚

移动能力通过独立开关和独立模块隔离。发生问题时关闭移动访问即可停止非回环 TLS 服务；不删除供应商、路由、模型健康或用量数据。移动客户端回滚只影响自身应用，桌面现有 `127.0.0.1:11435` 接口和凭证不需要迁移或重签发。
